# سیستم عملیات آژانس سئو (SEO Agency Operating System)

یک CRM/سیستم مدیریت پروژه شخصی برای متخصص سئویی که به‌طور هم‌زمان چند پروژه
(سئو ماهانه، طراحی سایت، محصول‌گذاری فروشگاهی و...) را مدیریت می‌کند. هدف
اصلی: هر روز صبح جواب این سؤال را بدهد — **«امروز باید روی چه چیزی کار
کنم؟»** — و علاوه بر آن ظرفیت کاری، سودآوری هر پروژه و سلامت کلی پروژه‌ها
را زیر نظر داشته باشد.

این مخزن بر اساس دو سند شما ساخته شده: PRD اولیه (ماژول‌های ۱ تا ۱۱) و
یادداشت‌های «دغدغه‌های یک مدیر سئو» (منطق مالی پروژه‌های ساعتی/قراردادی و
روتین‌سازی کارها). جزئیات تطبیق در بخش «چه چیزی ساخته شده» آمده است.

## پشته فنی

- **Backend:** Python 3.11، Django 5، Django REST Framework، JWT auth
- **دیتابیس:** PostgreSQL 16
- **Frontend:** React 19 + TypeScript + Vite + Tailwind CSS v4 + React Query
- رابط کاربری کاملاً فارسی و راست‌به‌چپ (RTL) است.

## راه‌اندازی (توسعه محلی)

### پیش‌نیاز
PostgreSQL 16، Python 3.11+، Node 20+

### بک‌اند

```bash
cd backend
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # مقادیر را در صورت نیاز تغییر دهید

# ساخت دیتابیس (اگر با docker-compose بالا نیاورده‌اید)
createdb crm_seo   # یا از طریق psql: CREATE DATABASE crm_seo OWNER crm_seo;

python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

API روی `http://127.0.0.1:8000/api/` بالا می‌آید. مستندات مسیرها در پایین
همین فایل است.

### فرانت‌اند

```bash
cd frontend
cp .env.example .env   # آدرس API را در صورت نیاز تغییر دهید
npm install
npm run dev
```

روی `http://localhost:5173` باز می‌شود و با نام‌کاربری/رمزی که در بک‌اند
ساختید وارد شوید.

### یا با Docker Compose

```bash
docker compose up --build
```

(دیتابیس، بک‌اند و فرانت‌اند هم‌زمان بالا می‌آیند — پس از اولین اجرا یک‌بار
`docker compose exec backend python manage.py createsuperuser` را اجرا کنید.)

## چه چیزی ساخته شده (فاز ۱ + تکمیل ماژول‌های PRD)

| ماژول PRD | وضعیت | توضیح |
|---|---|---|
| ۱. داشبورد | ✅ | ظرفیت، درآمد، سلامت پروژه‌ها، پیشنهاد کارهای امروز |
| ۲. CRM مشتری | ✅ | فیلدهای کامل + شمارش پروژه فعال |
| ۳. مدیریت پروژه | ✅ | انواع پروژه/قرارداد، اولویت، وضعیت گردش‌کار |
| ۴. مدیریت تسک | ✅ | دسته‌بندی‌های استاندارد سئو (۳۲ مورد پیش‌فرض seed شده)، فیلد تکرار و ارزش تولیدشده |
| ۵. قالب پروژه سئو | ✅ | صفحه‌ی «قالب‌های تسک» برای ساخت/ویرایش + دکمه‌ی «اعمال قالب» روی هر پروژه |
| ۶. مدیریت پروژه ساعتی | ✅ | محاسبه دقیق طبق مثال‌های سند شما (پایین را ببینید) |
| ۷. Time Tracking | ✅ | تایمر Start/Pause/Stop زنده + ثبت دستی زمان |
| ۸. Capacity Planning | ✅ | مقایسه ظرفیت ماهانه با مجموع نیاز پروژه‌های فعال + هشدار اضافه‌بار |
| ۹. سیستم اولویت هوشمند | ✅ | امتیازدهی بر اساس فوریت موعد + اولویت پروژه/تسک + درآمد |
| ۱۰. تقویم | ✅ | نمای ماهانه با تسک‌ها روی روز موعدشان، رنگ‌بندی بر اساس اولویت |
| ۱۱. ردیابی کلمات کلیدی | ✅ | رتبه فعلی/هدف، تاریخچه رتبه، ثبت رتبه جدید در هر پروژه |

علاوه بر این ماژول‌های PRD، این‌ها هم اضافه شدند:

- **تکرار خودکار تسک‌ها**: وقتی تسکی با تکرار «هفتگی»/«ماهانه» انجام‌شده علامت
  بخورد، سیستم خودش نمونه‌ی بعدی را با موعد جدید می‌سازد (نیازی به یادآوری
  دستی نیست).
- **گزارش ماهانه خودکار**: تب «گزارش ماهانه» در هر پروژه، بدون هیچ کار
  دستی، فعالیت‌های انجام‌شده و ساعت کار به تفکیک دسته را از روی تسک‌ها و
  ثبت‌های زمان می‌سازد — دقیقاً ساختاری که در یادداشت‌های شما توصیف شده بود.
- **بازطراحی کامل ظاهر**: فونت Vazirmatn، پالت رنگ برند (بنفش/ایندیگو)،
  آیکون‌های lucide-react، کارت‌ها و دکمه‌های یکدست.
- **خروجی PDF گزارش ماهانه**: دکمه‌ی «دانلود PDF» در تب گزارش ماهانه —
  آماده برای ارسال مستقیم به مشتری.
- **نقش‌ها و اعضای تیم**: صفحه‌ی مدیریت تیم، با محدودیت دسترسی واقعی
  (Owner در برابر بقیه‌ی نقش‌ها) — جزئیات در بخش «نقش‌ها و اعضای تیم» پایین‌تر.
- **بریف محتوا با هوش مصنوعی**: از تب کلمات کلیدی هر پروژه، یک بریف کامل
  (Intent، ساختار H1/H2/H3، FAQ، کلمات مرتبط، لینک داخلی، طول پیشنهادی)
  با کلید Anthropic خودتان تولید می‌شود.
- **اعلان روزانه**: خلاصه‌ی «پیشنهاد امروز» از طریق ایمیل و/یا تلگرام.
- **اتصال Google Search Console**: خلاصه‌ی کلیک/ایمپرشن/CTR/رتبه و
  پرکلیک‌ترین کوئری‌ها و صفحات، در تب مخصوص هر پروژه.

### منطق مالی پروژه (مهم‌ترین بخش یادداشت شما)

برای هر پروژه، سیستم به‌جای «۲۰ میلیون = X ساعت»، این‌طور محاسبه می‌کند:

- **ساعت خریداری‌شده توسط قرارداد** = `مبلغ قرارداد (یا هدف درآمد ماهانه) ÷ نرخ ساعتی هدف`
- **ساعت واقعی موردنیاز** = عددی که خودتان به‌عنوان تخمین واقعی کار وارد می‌کنید
- **اختلاف (حاشیه/کسری)** = تفاوت این دو عدد
- **نرخ ساعتی واقعی** = `درآمد پروژه ÷ ساعت واقعاً ثبت‌شده`
- **وضعیت سودآوری**: سودآور / متعادل / کم‌سود / زیان‌ده — بر اساس نسبت «ساعت موردنیاز» به «ساعت خریداری‌شده»

مثال دقیقاً از سند شما تست شده: قرارداد ۲۰ میلیون + نرخ هدف ۵۰۰ هزار (=
۴۰ ساعت ظرفیت) با ۵۵ ساعت نیاز واقعی → سیستم آن را **«زیان‌ده»** با کسری
۱۵ ساعت نشان می‌دهد؛ همان قرارداد با نرخ هدف ۲۰۰ هزار (= ۱۰۰ ساعت ظرفیت) →
**«سودآور»**.

## مسیرهای اصلی API

همه مسیرها زیر `/api/` و نیازمند JWT (`Authorization: Bearer <token>`) هستند.

- `POST /api/auth/token/` — ورود (دریافت access/refresh)
- `GET/PATCH /api/accounts/me/` — پروفایل و ظرفیت ماهانه کاربر
- `/api/clients/` — CRUD مشتری
- `/api/projects/` — CRUD پروژه (شامل `financials` محاسبه‌شده در پاسخ)
- `POST /api/projects/{id}/apply-template/` — اعمال قالب تسک روی پروژه
- `GET /api/projects/{id}/monthly-report/?year=&month=` — گزارش ماهانه خودکار
- `/api/tasks/`, `/api/tasks/categories/`, `/api/tasks/templates/`
- `GET /api/tasks/today/` — تسک‌های امروز
- `/api/time/entries/` — ثبت‌های زمان
- `/api/time/timer/` + `/api/time/timer/{pause|resume|stop}/` — تایمر زنده
- `/api/keywords/` + `POST /api/keywords/{id}/record-rank/` — ردیابی کلمات کلیدی
- `/api/keywords/content-briefs/` + `POST .../generate/` — بریف محتوا با AI
- `GET /api/projects/{id}/search-console/?days=` — خلاصه سرچ کنسول
- `/api/accounts/team/` — مدیریت اعضای تیم (فقط Owner)
- `GET /api/dashboard/` — خلاصه‌ی کامل داشبورد

## راه‌اندازی یکپارچه‌سازی‌های اختیاری

این سه قابلیت با کلید/حساب خودتان فعال می‌شوند؛ بدون تنظیم، برنامه کاملاً
کار می‌کند و فقط پیام «تنظیم نشده» به‌جای آن بخش نشان داده می‌شود.

**۱. بریف محتوا با هوش مصنوعی**
یک کلید از [console.anthropic.com](https://console.anthropic.com) بگیرید و
در `backend/.env` قرار دهید:
```
ANTHROPIC_API_KEY=sk-ant-...
```
هزینه‌ی هر فراخوانی از حساب Anthropic خودتان کسر می‌شود.

**۲. اعلان روزانه (ایمیل / تلگرام)**
در `backend/.env`:
```
DIGEST_CHANNELS=email,telegram   # هر کدام را که می‌خواهید نگه دارید
DIGEST_EMAIL_TO=you@example.com
EMAIL_HOST=smtp.example.com
EMAIL_HOST_USER=...
EMAIL_HOST_PASSWORD=...
TELEGRAM_BOT_TOKEN=...           # از @BotFather بگیرید
TELEGRAM_CHAT_ID=...             # با getUpdates بعد از یک پیام به ربات پیدا کنید
```
اگر با `docker compose up` اجرا می‌کنید، سرویس `scheduler` هر روز راس ساعت
`DIGEST_TIME` (پیش‌فرض ۰۸:۰۰) خودش این را می‌فرستد. برای اجرای فوری/تستی:
`python manage.py send_daily_digest`.

**۳. اتصال Google Search Console**
1. در Google Cloud Console یک Service Account بسازید و Search Console API را فعال کنید؛ فایل JSON کلید را دانلود کنید.
2. ایمیل همان Service Account را در Google Search Console، به‌عنوان کاربر پراپرتی سایت اضافه کنید.
3. در `backend/.env`: `GOOGLE_SERVICE_ACCOUNT_FILE=/path/to/key.json`
4. در تب «سرچ کنسول» هر پروژه، آدرس دقیق پراپرتی (`https://example.com/` یا `sc-domain:example.com`) را وارد و ذخیره کنید.

## نقش‌ها و اعضای تیم

مدل کاربر از ابتدا آماده‌ی چند کاربره بودن ساخته شده. حساب اول شما نقش
**Owner** دارد و صاحب همه‌ی داده‌هاست. از صفحه‌ی «اعضای تیم» (فقط برای
Owner قابل مشاهده) می‌توانید همکار با نقش‌های SEO Specialist، Content
Writer، Developer، Designer یا Client Portal User اضافه کنید:
- اعضای تیم مشتری‌ها/پروژه‌های شما را می‌بینند، تسک انجام می‌دهند و زمان
  ثبت می‌کنند.
- فقط Owner می‌تواند مشتری/پروژه/قالب تسک بسازد، ویرایش یا حذف کند، و
  اعضای تیم را مدیریت کند.
- داشبورد «امروز چی کار کنم؟» برای هر عضو تیم بر اساس تسک‌های خودش
  شخصی‌سازی می‌شود؛ Owner همچنان کل تیم را می‌بیند.

## نکات امنیتی قبل از استفاده‌ی واقعی

- رمز عبور کاربر ادمین پیش‌فرض را حتماً عوض کنید.
- `SECRET_KEY` و رمز دیتابیس در `backend/.env` را برای هر محیط واقعی
  مقداردهی مجدد کنید (`.env` در گیت commit نمی‌شود).
- `DEBUG=False` و `ALLOWED_HOSTS` مناسب را پیش از استقرار عمومی تنظیم کنید.
